### 1.2 业务需求

#### 需求 FR-1：邮件实时接收与存储

**描述**：系统能够实时监听用户邮箱（Gmail、Outlook 等），获取新邮件并存储到本地数据库。

**业务流程**：
```
用户邮箱 ---(IMAP长连接)---> EmailService ---> 数据库
           （实时监听）

流程步骤：
1. 系统连接到用户邮箱（IMAP）
2. 监听 INBOX 文件夹的新邮件
3. 接收邮件信息（发件人、主题、正文、日期等）
4. 解析 MIME 格式，提取纯文本和 HTML
5. 保存到数据库，标记为"新邮件"
```

**接受标准**：
- ✅ 邮件到达邮箱 1 秒内系统检测到
- ✅ 邮件完整性 100%（不丢失任何信息）
- ✅ 支持 Gmail、Outlook、企业邮箱
- ✅ 邮件解析准确率 > 99%

---

#### 需求 FR-2：AI 智能分类

**描述**：系统使用 OpenClaw 框架和大语言模型，根据邮件内容自动分类。

**业务流程**：
```
邮件内容 ---> OpenClaw Agent ---> 分类结果 ---> 数据库
             (多轮推理)

分类流程：
1. Agent 接收邮件文本（标题+内容摘要）
2. Agent 自主调用工具获取上下文：
   a. 查询发件人是否是重要联系人
   b. 检查邮件中的关键词
   c. 查询用户的分类规则
3. Agent 基于上述信息综合判断
4. 返回分类结果：{category, confidence, reasoning}
5. 系统保存分类结果到数据库
```

**分类类别**：
- 📧 **work**：工作相关（会议、项目、报告等）
- 👤 **personal**：个人事务（朋友、家庭、社交）
- 🛍️ **shopping**：购物相关（订单、收据、发货）
- 📢 **marketing**：广告营销（推送、促销、新闻）
- ⛔ **spam**：垃圾邮件（钓鱼、诈骗）
- 📌 **other**：其他

**接受标准**：
- ✅ 分类准确率 > 85%
- ✅ 分类延迟 < 5 秒
- ✅ Agent 推理成功率 > 95%
- ✅ 能解释分类理由（显示推理过程）

---

#### 需求 FR-3：重要性评分与优先级提醒

**描述**：系统检测邮件重要性，对重要邮件通过 Telegram 实时通知用户。

**业务流程**：
```
邮件入库 ---> ImportanceSkill ---> 评分(1-10) ---> 判断 ---> Telegram通知
                                              (>=7?)

评分因素：
• 发件人重要性（是否在重要联系人名单）
• 邮件内容关键词（包含"紧急""会议"等）
• 用户历史行为（用户经常阅读该发件人的邮件）
• 邮件主题敏感词汇

通知示例：
📧 重要邮件来了！
发件人：boss@company.com
主题：下午3点会议，请参加
摘要：关于Q1季度业绩评审...
重要性：⭐⭐⭐⭐⭐ (8/10)

[标记重要] [标记垃圾] [查看详情]
```

**接受标准**：
- ✅ 重要邮件通知延迟 < 2 秒
- ✅ 误报率（将垃圾邮件标为重要）< 5%
- ✅ 漏报率（将重要邮件标为普通）< 10%
- ✅ 用户可自定义重要性阈值

---

#### 需求 FR-4：邮件摘要生成

**描述**：系统自动生成邮件的简明摘要，帮助用户快速了解内容。

**业务流程**：
```
邮件正文 ---> SummarizationSkill ---> 摘要 ---> 保存+显示

摘要包含：
• 一句话总结（30-50字）
• 关键点列表（最多3个）
• 需要采取的行动（如有）

示例：
原邮件：（500字的项目进度报告）

摘要生成：
一句话：Q1项目进展顺利，完成度87%，下周进行第二阶段测试。
关键点：
  • 完成度：87%
  • 下阶段：第二阶段测试
  • 参与人：PM张三、开发李四
待办：确认测试时间表
```

**接受标准**：
- ✅ 摘要生成延迟 < 3 秒
- ✅ 摘要长度控制在 50-100 字
- ✅ 关键信息保留率 > 90%

---

#### 需求 FR-5：用户交互与反馈

**描述**：用户通过 Telegram 与系统交互，可进行邮件标记、归档、反馈分类等操作。

**业务流程**：
```
用户操作 ---> Telegram Webhook ---> 后端处理 ---> 数据库更新 ---> 邮箱操作

支持的操作：

1. 标记已读
   用户点击[标记已读] ---> 系统调用IMAP API ---> 邮件标记为已读

2. 标记垃圾
   用户点击[标记垃圾] ---> 系统移动到Trash/垃圾文件夹 ---> 反馈给AI

3. 反馈分类
   用户选择"这个分类错了，应该是[category]" ---> 系统记录反馈 ---> AI下次改进

4. 查看详情
   用户点击[查看详情] ---> 系统发送邮件完整内容 ---> 显示在Telegram

5. 管理规则
   用户发送 /rules ---> 系统列出所有规则 ---> 用户可添加/删除规则
```

**接受标准**：
- ✅ 用户操作反馈延迟 < 1 秒
- ✅ 操作成功率 > 99%
- ✅ Telegram 消息格式美观易读
- ✅ 支持至少 5 种用户操作

---

#### 需求 FR-6：邮件搜索与过滤

**描述**：用户可以按照各种条件搜索和过滤邮件。

**搜索/过滤条件**：
- 📍 按分类（work, personal, marketing 等）
- 🔍 按发件人
- 📅 按日期范围
- ⭐ 按重要性（1-10）
- 🏷️ 按标签/标记
- 🔎 按关键词（在发件人、主题、内容中搜索）

**接受标准**：
- ✅ 搜索结果返回时间 < 1 秒（1000 邮件内）
- ✅ 支持多条件组合搜索
- ✅ 搜索准确率 > 95%

---

#### 需求 FR-7：每日摘要与统计

**描述**：系统每天定时生成邮件统计和摘要，通过 Telegram 发送给用户。

**每日摘要内容**：
```
📊 今日邮件摘要 (2026-03-13)

📈 数据统计
  总邮件数：47 封
  未读邮件：12 封
  
🗂️ 分类分布
  工作：15 封
  个人：8 封
  购物：5 封
  营销：18 封
  垃圾：1 封

⭐ 重要邮件（4 封）
  • boss@company.com: Q1财报分析
  • mom@personal.com: 周日聚餐确认
  • amazon: 订单已发货
  • bank: 账户异常提示

📅 时间分析
  最活跃时段：09:00-12:00（21 封）
  最活跃发件人：colleagues@company.com（5 封）
```

**接受标准**：
- ✅ 每天固定时间发送（如 21:00）
- ✅ 统计数据准确率 100%
- ✅ 摘要完整包含工作、个人、垃圾邮件

### 1.3 User Story

#### User Story 1：邮箱连接与实时监听

**作为一个** 职场人士  
**我想要** 系统能自动连接我的 Gmail 邮箱，实时获取新邮件  
**以便于** 我不错过任何重要邮件

**验收标准**：
- ✅ 能正确输入 Gmail 账户密码（应用专用密码）
- ✅ 新邮件在 1 秒内被系统检测
- ✅ 邮件信息完整（主题、发件人、内容等）
- ✅ 系统意外断开时能自动重新连接

**优先级**：🔴 **高**

---

#### User Story 2：AI 分类的智能推理

**作为一个** 学生  
**我想要** AI 能智能分类我的邮件（工作、个人、垃圾等）  
**以便于** 我快速找到重要邮件，不被垃圾邮件淹没

**验收标准**：
- ✅ 至少 85% 的邮件分类正确
- ✅ 系统能解释为什么这样分类（显示推理过程）
- ✅ 如果我纠正分类，系统下次能学到改进

**优先级**：🔴 **高**

---

#### User Story 3：重要邮件秒级通知

**作为一个** 经理  
**我想要** 重要邮件到达时，Telegram 能立即通知我  
**以便于** 我能及时处理紧急事务

**验收标准**：
- ✅ 重要邮件在 2 秒内通过 Telegram 通知
- ✅ 通知包含完整的邮件预览（发件人、主题、摘要）
- ✅ 我可以在 Telegram 中点击按钮执行操作（标记、归档等）
- ✅ 不会因为垃圾邮件频繁打扰（误报 < 5%）

**优先级**：🔴 **高**

---

#### User Story 4：邮件搜索与回顾

**作为一个** 项目经理  
**我想要** 能快速搜索以前的邮件（按发件人、日期、关键词）  
**以便于** 我回顾历史沟通记录

**验收标准**：
- ✅ 1000 封邮件的搜索在 1 秒内完成
- ✅ 支持多条件搜索（如：工作类邮件 + 发件人是boss）
- ✅ 搜索结果准确率 > 95%

**优先级**：🟡 **中**

---

#### User Story 5：邮件规则自定义

**作为一个** 资深用户  
**我想要** 能自定义邮件分类规则（如：来自"noreply@"的自动标记为垃圾）  
**以便于** 系统分类更符合我的习惯

**验收标准**：
- ✅ 能通过 Telegram 命令添加/删除规则
- ✅ 规则格式简单易理解（条件-动作式）
- ✅ 新规则立即生效

**优先级**：🟢 **低**

### 2.2 关键用例详述

#### UC4：AI 邮件分类 (详细描述)

**用例名称**：AI 邮件分类

**参与者**：系统（EmailClaw）、OpenClaw Agent

**前置条件**：
- 邮件已成功接收并存储到数据库
- ClassificationSkill 已初始化

**主流程**：

```
1. 系统读取数据库中标记为"待分类"的邮件
2. 提取邮件的 {主题, 发件人, 内容摘要}
3. 调用 ClassificationSkill.execute(email)
4. 系统创建 OpenClaw Agent 实例
5. Agent 接收任务："请分类这封邮件"
6. Agent 决策是否需要工具帮助
   a. IF 需要查询发件人信息：
      - 调用 get_sender_info(from)
      - 返回：{name, isImportant, emailCount, ...}
   b. IF 需要检查关键词：
      - 调用 check_keywords(content, keywords=['会议','报告','deadline',...]
      - 返回：{keyword: found_count, ...}
   c. IF 需要查询重要联系人：
      - 调用 lookup_contacts()
      - 返回：[{email, name, category}, ...]
7. Agent 综合分析上述信息
8. Agent 返回分类结果：
   {
     category: 'work' | 'personal' | 'shopping' | 'marketing' | 'spam' | 'other',
     confidence: 0.92,
     reasoning: "邮件主题包含'会议'，发件人是CEO，判定为工作邮件",
     toolsUsed: ['get_sender_info', 'check_keywords']
   }
9. 系统保存分类结果到 Classification 表
10. 更新 Email 表中的 category 和 confidence 字段
```

**备选流程**：

```
A. Agent 分类失败（返回错误）
   A1. 系统记录错误日志
   A2. 使用备选方案：规则引擎分类
   A3. 保存为 category='other'，confidence=0.5
   A4. 继续处理下一封邮件

B. Agent 超时（>5秒无响应）
   B1. 系统终止 Agent 执行
   B2. 记录超时日志
   B3. 使用备选方案：规则引擎分类
```

**后置条件**：
- 邮件的 category 和 confidence 已更新
- 分类结果已持久化到数据库
- 邮件状态从"待分类"变为"已分类"

**非功能需求**：
- 分类延迟 < 5 秒
- 分类准确率 > 85%
- Agent 成功率 > 95%

## 系统约束条件

### 4.1 技术约束

1. **编程语言**：TypeScript + Node.js
2. **框架限制**：必须使用 OpenClaw 框架进行AI分类
3. **数据库**：仅支持PostgreSQL（开发测试使用SQLite可能出现问题）
4. **通知渠道**：仅支持Telegram（不支持邮件通知、短信等）
5. **IMAP兼容性**：系统仅支持IMAP协议，不支持POP3

### 4.2 业务约束

1. **单用户系统**：当前版本为单用户设计（未实现多用户隔离）
2. **邮箱限制**：仅支持IMAP兼容的邮箱（Gmail、Outlook等）
3. **分类数量**：固定6种分类，用户不能自定义分类
4. **API限流**：Claude API 有速率限制（基于API额度）
5. **数据保留**：邮件数据仅保留180天（自动删除）

### 4.3 法律与合规

1. **用户数据**：用户邮件数据完全私有，不与第三方共享
2. **GDPR合规**：支持数据导出和删除功能
3. **隐私保护**：IMAP密码使用加密存储，不可读取
4. **开源协议**：项目采用MIT协议

### 4.4 文档约束

1. 所有代码必须有清晰的注释
2. 每个API端点必须有文档说明
3. 数据库Schema必须附带数据字典
4. 部署说明必须完整详细
